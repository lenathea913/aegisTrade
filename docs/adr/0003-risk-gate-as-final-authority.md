# ADR 0003 — The risk gate is the final authority

- **Status:** accepted
- **Date:** 2026-11-15

## Context

The platform's reason to exist is that a strategy must not be able to trade beyond
the operator's risk budget, even when the strategy is wrong, buggy, or generated by
an LLM. A convention ("always call the risk engine first") is not enforcement.

## Decision

- Strategies emit **`OrderIntent` only** — a proposal with a mandatory stop-loss.
- `RiskGate.evaluate(...)` returns a `RiskDecision`. Approvals carry the checks that
  passed and the accepted `max_risk_amount`; rejections list **every** violated rule
  with a stable machine-readable code.
- `ApprovedOrder` is the only object `ExecutionGateway` accepts, and the gateway
  also checks `isinstance` at runtime for untyped callers, raising
  `UnapprovedOrderError`.
- `Order.from_approved()` is the only constructor of an executable order.
- `TradingPipeline` is the sole composition of gate → gateway → ledger; services call
  it rather than wiring the pieces.
- The kill switch and the staleness window are bound into `RiskGate` from settings,
  so a caller cannot forget them.

## Consequences

**Positive**

- "No order without approval" is a type-level guarantee plus a runtime backstop plus
  an integration test that tries to bypass it.
- Every rejection is explainable after the fact from `audit_logs`.

**Negative**

- Adding a new order type or venue requires touching the gate contract.
- Rejected intents are recorded as audit events only; there is no relational row per
  rejection yet (a candidate follow-up).

## Alternatives considered

- **Risk checks inside the gateway.** Rejected: mixes policy with transport and makes
  it easy to add a second gateway that skips checks.
- **Advisory risk warnings.** Rejected: warnings are ignored; hard rejection is the
  point.
